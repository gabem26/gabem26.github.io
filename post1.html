Hardening SSH in 10 minutes

2026-10-28 · 4 min read · #linux #security

A fresh server with SSH on port 22 gets hit by bots within minutes. Here is the short checklist I run on every new machine before doing anything else.

1. use keys, not passwords

Generate a key on your laptop and copy it over:

ssh-keygen -t ed25519
ssh-copy-id user@your-server

2. lock down sshd_config

Edit /etc/ssh/sshd_config and set:

PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
AllowUsers youruser

Keep a second session open, then reload with sudo systemctl reload sshd and test before closing anything.

3. add fail2ban

sudo apt install fail2ban
sudo systemctl enable --now fail2ban

It bans IPs that keep failing to log in. Cheap and effective.

4. optional extras

  • Move SSH off port 22 to cut log noise (not real security on its own)
  • Enable a firewall: ufw allow OpenSSH && ufw enable
  • Turn on automatic security updates

That's it. Ten minutes, and you're ahead of most servers on the internet.
